# V2-A1.20D full-text Boundary 机制修复

日期：2026-07-18

证据等级：post-stop diagnostic。A1.20D 是在 A1.20C 严格失败后、按用户允许降低实验严谨性开展的机制修复，不追溯改写 A1.20C，也不构成三组 fresh seed formal。

## 核心判断

A1.20C 的残余错误不只是优化器没有把既有目标练好。factorized compiler 的 section 推断方向不完整：旧 forward 先用粗 operation 边界解码 entity，再用 entity 末端细化 operation，却没有把细化后的第一个 operation 位置反馈给 entity decoder。N5 的第五个实体最靠近 program section，因而被粗边界截断；同一套阈值在 N4 又可能接纳伪第五实体。

修复把 section 推断改为三遍闭环：

1. 用粗 operation 边界得到第一遍 entity table；
2. 用 entity 末端约束得到细化 operation sequence；
3. 用细化后的第一个 operation 位置重新解码最终 entity table。

这不是新增 oracle span，也没有改变 frozen Qwen、frozen A1.19H core 或正式执行语义。它使“entity section 在 operation 开始前结束”和“operation section 在 entity 结束后开始”成为相互一致的约束。修复后无需重新训练，原有 `ENTITY_PAIR_GAIN_THRESHOLD=12.0` 即可同时拒绝 N4 伪实体并接受 N5 真实体。

## 因果证据

容量阈值扫描先显示了表面不可分：

- 旧粗边界下，routing N4 需要约 `10` 才能拒绝伪第五实体；
- routing N5 又需要不高于约 `4.5` 才能保留真第五实体。

进一步比较粗 operation boundary 与 refined operation start 后，N4 伪第五实体的 pair gain 约为 `5–8`，N5 真第五实体约为 `13–18`。因此真正缺失的不是另一个全局阈值，而是 refined program boundary → entity decoder 的反向信息。三遍解码只改变这一条因果边，原 checkpoint 随即跨过 N5 Gate，支持该定位。

## 架构解释与边界

这轮结果改变了对 A1.20C 失败的解释：负梯度冲突是真实现象，但其中一部分来自错误的单向 section 因果图。训练同时要求 reader 在不一致的 entity/program 边界下满足 local anchor 与 frozen-core state，自然会出现强冲突。闭合 section 约束后，已有权重已足以运行，说明继续单纯调 loss 权重或延长训练不是主要答案。

正面结论仅是：当前 full-text hybrid candidate 的核心执行机制已从“明显失败”恢复到“强诊断正证据”。它仍不是 A1.20 formal `3/3`：

- canonical 完整矩阵 artifact 明确标记 `formal_gate=false`；
- 只有一个 reader/core/data 起点；
- 另外两条路径只改变 batch schedule；
- routing 是保留 COPY/SWAP 代数的表面改写；
- 没有公平训练预算和完整成本审计。

因此 A1.20C 的历史失败保持不变，A1.20D 只作为后续 A1.21P 候选机制证据。
