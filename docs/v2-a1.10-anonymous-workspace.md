# V2-A1.10：完整文本匿名工作区与通用循环推理器

日期：2026-07-16

状态：已完成；overfit32 passed，formal `0/3`，总 Gate failed

证据范围：完整 frozen Qwen3.5-2B token hidden → 匿名 `K=8` latent workspace → 两层共享 recurrent Transformer reasoner

## 1. 核心问题与归因边界

A1.9 已证明 oracle-role-segmented Qwen hidden 能驱动显式三寄存器结构化核心。A1.10 按当前决策同时删除两类 scaffold：第一，不再用 character span 或 token mask 指出 initial value、operation family、source、target 和 query；第二，不再使用三寄存器 state slots、register keys、typed role adapter 或 COPY/SWAP 专用 transition。

因此 A1.10 是架构级联合切换，不是单变量实验。通过只能说明“完整文本读取、匿名工作区和通用循环推理器的组合”在当前任务上成立；失败不能单独归因到 boundary parsing、slot binding、循环优化或 readout 中的某一项。后续诊断必须重新拆变量，不能用本轮结果声称某个子模块被独立否定。

## 2. 冻结架构合同

### 2.1 输入边界

- 文本基座固定为 Qwen3.5-2B revision `15852e8c16360a2fea060d615a32b45270f8a8fc`，FP16、完全冻结；
- cache 保存最后一层完整 token hidden、attention mask、token length、example id 和 fingerprint；
- 不保存 offset mapping、character span、operation token mask、role pooled hidden、input ids 或任何 oracle role tensor；
- 无静默截断；cache audit 必须验证 source data hash、fingerprint、shape、finite、跨 split overlap 和禁用字段。

### 2.2 匿名工作区

- `K=8`，`D_latent=256`；
- 八个 learned latent queries 共享同一个 full-source cross-attention 读取器；
- latent slot 没有 amber/cobalt/jade、value、operation、query 或 control 类型；
- 不存在 register embedding、register key、三寄存器 slot、role adapter、operation embedding 或任务专用 pointer；
- slot readout 先对最终归一化 workspace 做 permutation-invariant mean pooling，再进入监督头。

“匿名”指内部 slot 不与数据本体绑定，不表示八个 learned query 参数必须相同。slot permutation 必须保持 readout 不变，作为结构审计而非能力 Gate。

### 2.3 通用 recurrent reasoner

- 两个通用 pre-norm Transformer block；每个 block 为 latent self-attention、对完整 source token 的 cross-attention 和 Dense FFN；
- 同一组两层 block 在所有 recurrent step 完全共享；
- 无 COPY/SWAP operator、source/target pointer、hard re-embedding、teacher state、oracle reset、绝对 step embedding或按 operation 注入的外部 token；
- 训练统一运行 16 个 recurrent steps，模型前向不接收每例 operation mask 或 program length；短程序在监督侧把最终状态重复到第 16 步，要求模型从完整文本自主学会停止更新；
- 正式评测对 T1–16 统一运行 16 个 recurrent steps；前 `L` 步对齐真实操作轨迹，剩余步要求最终状态保持。T20/T24/T32 分别运行 20/24/32 步。该全局预算仍由实验控制面给定，因此 A1.10 不验证自主 stop head。

### 2.4 输出与监督

- `state_head` 从每一步匿名 workspace 的 pooled latent 解码 `3 × 10` 状态标签；这只是外部任务 readout，不对应三个内部 slot；
- `answer_head` 只读取最后一步 pooled latent，不能读取 source hidden、标准答案、teacher trace 或 state label；
- 唯一优化目标为逐步 state CE 与 final answer CE，权重均为 `1.0`；
- 不加入 family/source/target/query reconstruction、pointer、mapping、prototype closure、register identity 或答案旁路损失。

## 3. 数据、训练与停止规则

沿用 A1.8 三组独立数据，不重新使用 A1.9 role cache：

| run | data seed | model seed |
| --- | ---: | ---: |
| 1 | `20260721` | `20261021` |
| 2 | `20260722` | `20261022` |
| 3 | `20260723` | `20261023` |

训练保持 T1–16 batch 内长度均衡，batch size `32`，AdamW，learning rate `3e-4`，最多 `4000` steps，validation 每 `200` steps。checkpoint 以 validation 最差长度 trajectory、final state 和 answer 的词典序综合分数选择，不以 aggregate average 掩盖局部失败。

先运行 length-balanced overfit32。overfit32 必须在所有 T1–16 上同时达到 trajectory full exact `1.0`、final state full exact `1.0` 和 answer accuracy `1.0`；失败则停止正式三 seed，不通过加 role loss、oracle mask、register slot 或任务专用 transition 修补。

overfit32 通过后，三个正式 seed 都要训练和评测。某个正式 run 未通过普通 Gate 时，该 run 不执行 hidden intervention，但其余 seed 仍运行，以区分稳定架构失败与单次优化失败。

## 4. 正式 Gate

每个长度独立报告 trajectory full、final state full、state token、answer 和 answer/state consistency。正式阈值为：

- short T1–6：每个长度 trajectory、final state、answer 均不低于 `0.95`；
- supported T8/T12/T16：每个长度上述三项均不低于 `0.95`；
- relation T8/T12/T16：每个长度上述三项均不低于 `0.95`；
- supported 与 relation T20/T24：每个长度 trajectory、final state、answer 均不低于 `0.90`；
- causal core aggregate trajectory、final state、answer 均不低于 `0.95`；
- 所有正式 split aggregate state token accuracy 不低于 `0.995`；
- architecture/cache integrity 必须通过；
- T32 只作诊断，不进入总 Gate。

三个 run 必须全部通过才算 A1.10 formal 通过。普通 Gate 先于因果干预写盘，禁止用干预结果反向选择 checkpoint。

## 5. 因果干预

只对普通 formal 已通过的 run 执行：

- text prefix、单步 replacement、deletion、operation shuffle、query swap：重新渲染完整文本并重新编码 Qwen hidden，按新文本重新计算 oracle；
- same-answer/different-trajectory：交换完整 source hidden，答案保持相同但目标轨迹改变；
- no-source：完整 hidden 置零；
- independent-source shuffle：跨样本打乱完整 hidden、保留原标签；
- disable-recurrence：只保留 READ 后 workspace；
- slot permutation：只作匿名结构不变性审计。

反事实 prefix/replacement/deletion/shuffle/query-swap 和 same-answer 新目标准确率不低于 `0.95`；必要样本对旧 trajectory 的保留率不高于 `0.05`；no-source、independent-source shuffle 和 disable-recurrence 的 trajectory full 不高于 `0.20`。slot permutation 的 logits 最大绝对差必须小于 `1e-5`。

## 6. 允许与禁止的结论

若 3/3 formal 与 causal Gate 全部通过，可以声称：当前固定语法 COPY/SWAP 任务中，完整 frozen Qwen token hidden 可在没有 oracle spans 和显式寄存器 scaffold 的情况下，通过匿名 `K=8` workspace 与通用共享 recurrent Transformer 形成因果忠实的逐步推理。

即使通过，也不能声称 matched text-CoT Pareto、自主停止、动态 K、自然语言 audit、MoE、多模态或完整 V2-A 已成立。若失败，只能否定本轮联合配置；由于同时切换 boundary、workspace 和 reasoner，必须用后续消融定位，不能直接否定所有匿名 latent reasoning。

## 7. 执行中的合同修正

第一次 run 1 训练后、正式 full evaluation 前，发现 validation 曾让 T1 样本只运行 1 步、T8 只运行 8 步，而训练时所有样本统一运行 16 步，final answer 也只在第 16 步受训。该预算不一致会系统性低估短程序答案，并偏离第一版固定 `T` reasoner 合同。

这轮错误预算产生的 overfit/formal 与 run-1/formal checkpoint 已删除，没有进入正式结果。修正后，T1–16 validation/formal 均运行 16 步；前 `L` 步对齐真实状态，剩余步要求状态保持。T20/T24/T32 运行 20/24/32 步。修正版 overfit32 重新训练并通过，三个 formal run 也全部从头训练。cache 合同不受该错误影响，保留并通过重新审计。

## 8. 正式结果

修正版 overfit32 的 best step 为 `800`，在 step `1000` 连续第二次达到 T1–16 trajectory、final state、answer 全 `1.0`，训练 `271.91` 秒。它证明实现与优化链可以记忆 32 条样本，但不提供分布泛化证据。

三个 run 的 short aggregate trajectory 只有 `0.002604/0.003906/0.002604`，causal-core trajectory 全为 `0`。T16/T24 final state 和 answer 明显高于随机，但 trajectory 几乎为零；训练集均衡诊断的 trajectory 也只有 `0.005859/0.001953/0`，说明问题不是 relation holdout 或长度外推才出现，而是当前 full-text anonymous reasoner 没有在正式分布上学成逐步状态更新。

因此 **A1.10 formal 为 `0/3`，总 Gate failed。**所有普通 formal 都失败，按预注册没有生成 counterfactual Qwen cache，也没有运行 prefix/replacement/deletion/shuffle/query-swap、same-answer、no-source、source shuffle、disable-recurrence 或 slot-permutation 干预。不能把“未运行”写成干预失败，也不能用 final answer 约 `0.54–0.61` 代替 trajectory Gate。

## 9. 成本与证据边界

- 三组 cache 各 `22,784` 条，train fingerprint 两两 overlap 为 `0`；
- 三组完整 token hidden 共 `9,046,290` source tokens、`38,358,822,720` bytes；
- Qwen 净编码共 `4,767.62` 秒，不含模型/tokenizer 首次加载；峰值 allocated memory 约 `5.18` GB；
- 三 run 共训练 `384,000` examples、`6,144,000` recurrent transitions、`3,256.60` 秒；
- trainable reasoner 为 `3,434,536` 参数；
- cached batch-32 训练 benchmark 为 `0.18009` 秒/step；T16 inference 为 `0.03156` 秒/batch，T24 为 `0.07378` 秒/batch；
- benchmark 不含在线 Qwen 加载/编码，也没有 matched text-CoT 对照，因此不是 Pareto 证据。

可以成立的结论是：目标形态的 full-token、anonymous `K=8`、共享通用 Transformer recurrence 已真实实现并能 overfit，但当前联合训练合同无法在正式数据上形成逐步推理，失败在三个独立 seed 上稳定复现。不能成立的结论是：full-text boundary、匿名 workspace 或通用 reasoner 中某一个已被单独否定；本轮同时切换三者，无法做单因子归因。

当前对 V2-A 最终形成 matched text-CoT 质量—成本 Pareto 的工程判断下调为 `30%–45%`、中心约 `37%`；完整白皮书 V2 为 `14%–28%`。这不是统计置信区间。下调来自首个高保真联合配置 `0/3` formal，而不是认为所有 latent architecture 已被证明不可行。

## 10. 下一步

下一轮不继续直接增大 K、T、层数或训练步数，也不解冻 Qwen、加入答案旁路或用 role loss 暗中恢复本轮已删除的 scaffold。先做两个对称诊断：

1. `A1.11-Boundary`：完整 Qwen token hidden → learned typed role reader → frozen A1.8 core，只测试删除 oracle spans；
2. `A1.11-Reasoner`：oracle typed role sequence → anonymous `K=8` generic reasoner，只测试删除显式 register core。

后续状态（2026-07-16）：A1.11 已完成。Boundary strict-overfit pointer Gate failed；最终 exact-symbolic Reasoner overfit passed、formal `0/3`。因此 A1.10 不是纯组合故障，当前主要独立失败源位于 anonymous binding／generic transition／readout objective 这一整臂。最新真源改见 `docs/v2-a1.11-fault-localization.md` 与 `tmp/V2-A1.11 result.md`。

若只有 Boundary 失败，问题在 full-text role discovery；若只有 Reasoner 失败，问题在匿名状态绑定/通用 transition；若两者都通过但联合失败，问题在接口组合与联合优化。两个诊断的正式合同须另行预注册，本轮不启动。
