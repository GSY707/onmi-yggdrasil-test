# V2-A1.20B learned full-text Boundary 实验记录

日期：2026-07-17

状态：已停止；overfit32 通过，run-1 训练内 heldout validation eligibility 失败，未进入 formal split、causal、run-2/run-3、A1.21P 或 A1.22A

## 1. 结论

A1.20B 没有通过。冻结 A1.19H generalized hybrid core 后，完整文本 Boundary 可以记住 32 条样本，也能从冻结 Qwen hidden 学到部分局部标签，但不能在未见样本上稳定生成一套相互一致的实体表与执行程序。run-1 固定 5000 step 完成后，2048 条 validation 的 trajectory/final-state/answer 为 `0.297363/0.409668/0.608887`，最差 `N×T` 单元的 mapping/trajectory/answer 为 `0.315341/0/0.227273`，远低于进入正式 split 的 `0.995` eligibility。

失败不在冻结 core。诊断中把 Boundary 的全部 value、mask、family、source、target、query 替换为 oracle 后，trajectory/final/answer 全部恢复 `1.0`。主要错误来自匿名实体的初值绑定与 source/target 地址绑定；family 序列是次要但实质的错误源，entity presence 与 query 不是 trajectory 主瓶颈。

更深一层的问题是当前训练接口切断了执行级信用分配。operation mask 使用阈值，family/source/target/query 使用 `argmax` 后才进入冻结 core，因此 state CE 只能直接训练连续 value payload，不能直接训练这些离散控制 logits。它们依赖彼此独立的局部 CE；局部准确率在长程序中乘法组合后，完整程序准确率迅速归零。这不是增加 seed、延长当前训练或提高 GPU 功率可以解决的问题。

## 2. 实验合同

Boundary 的唯一输入是冻结 `Qwen/Qwen3.5-2B` revision `15852e8c16360a2fea060d615a32b45270f8a8fc` 的完整 last hidden 与 attention mask。cache 不保存 input IDs、oracle span、role tensor、entity mask、operation mask 或答案 metadata，也不静默截断。

模型使用共享 entity query、query role query，以及按操作位置展开的 family/source/target role query，自主预测：

- entity 与 operation presence；
- 每个实体的连续初始 value payload；
- 每步 operation family；
- 每步 source/target entity pointer；
- query entity pointer。

预测的 value softmax 通过冻结 A1.19H value initializer 形成连续 payload；预测的离散控制通过 equality-only handles 驱动冻结 core。core 不解冻，不增加直接答案头，answer 仍只读取最终状态。正式 answer loss 权重为 `0`。

训练数据覆盖 `N=2,3,4`、`T=1...16`。每个 batch 同时覆盖全部 16 个长度，并使三种实体数的样本数差不超过 1。该采样器在正式启动前修正并加入回归测试，避免旧实现从排序 cell 重复取前部而偏向短长度与 `N=2`。

## 3. 启动前吞吐优化

本轮在正式训练前先审计 cache 与训练热路径，避免重复 A1.19H 早期的逐标量 Python→CUDA 写入和同步问题。

Qwen 编码以 32 条、最长 563 token 的真实文本做 batch benchmark：batch `8/12/16` 分别为 `2339/2602/2536` real tokens/s，峰值分配显存约 `4.30/4.56/4.83 GB`，因此选择 batch 12。run-1 train/validation cache 共编码 `18,432` 条、`5,594,417` source tokens，纯编码耗时 `2037.67s`；train 最长 587 token，validation 最长 575 token。cache audit 的 schema、数据 hash、source audit、shape、finite、fingerprint、cross-split overlap、oracle 禁止项与 no-truncation 全部通过。

正式训练不重复运行 Qwen，只从 mmap FP16 cache 取 hidden。训练索引序列预生成，固定 shape，validation 聚合只执行一次。额外测试了后台 pinned-memory prefetch：同步路径为 `4.9925 step/s`，prefetch 为 `4.6897 step/s`，速度比 `0.939×`，且 final loss 与参数不完全等价。因此正式路径保留更快、更确定的同步 mmap→GPU 搬运，没有为了提高表面 GPU 功率采用无收益并发。

Boundary 仅约 `2.768M` 可训练参数，冻结 core 约 `1.322M`，显存使用约 `1.46GB`。小模型、batch 16 与每 200 step 的完整 validation 使瞬时功率仍可能较低；正式判断使用 step/s、端到端 wall time 与数值等价，而不是把功率本身当作 Gate。run-1 完成 5000 optimizer steps、80,000 processed examples，训练含 validation 用时 `1611.57s`，平均 `3.1026 step/s`。

## 4. Overfit 与 run-1 结果

overfit32 在 step 900 形成稳定严格通过；mapping、trajectory、final state、answer 全为 `1.0`，continuous payload cosine 为 `0.999952`，core hash 不变。这证明实现与容量能够记住小样本，不证明规则泛化。

run-1 使用 reader/data/core seed `20262011/20261951/20261961`，从 fresh Boundary 初始化训练固定 5000 step。best checkpoint 按最差 cell 的 mapping、trajectory、answer 与 aggregate state-token 的字典序选择，落在 step 4000。

| 指标 | Validation aggregate | 最差 N×T cell / Gate |
| --- | ---: | ---: |
| trajectory full exact | `0.297363` | `0` |
| final state full exact | `0.409668` | 未通过 |
| state token accuracy | `0.547742` | Gate `0.995` |
| final answer accuracy | `0.608887` | `0.227273` |
| mapping minimum | `0.536018` | `0.315341` |

单项 mapping aggregate 为 entity presence `1.0`、operation presence `0.809082`、value `0.621358`、family `0.891831`、source `0.547966`、target `0.536018`、query `0.932129`。局部准确率不能代表完整边界程序正确。

## 5. 联合错误与长度/实体数退化

逐样本联合 exact 更直接地揭示了失败：完整 Boundary 七类输出同时正确的比例只有 `0.087891`，完整 program（operation presence + family + source + target）只有 `0.118652`，source/target/query 地址同时正确只有 `0.133301`。

实体数量增加时，匿名实体绑定快速崩溃：

| 分组 | 全部初值正确 | 全部 source 正确 | 全部 target 正确 | 全部 Boundary 正确 |
| --- | ---: | ---: | ---: | ---: |
| N2 | `0.967789` | `0.322108` | `0.300146` | `0.229868` |
| N3 | `0.172767` | `0.121523` | `0.128843` | `0.032211` |
| N4 | `0.007331` | `0.082111` | `0.068915` | `0.001466` |

程序变长时，ordered operation extraction 同样失效：T1–4 的完整 program 为 `0.410156`，T5–8 为 `0.054688`，T9–12 为 `0.009766`，T13–16 为 `0`；T13–16 的 source 与 target 全序列 exact 也均为 `0`。

这说明模型学到的是若干边际分类规律，而不是一个可泛化的“文本→实体表→有序程序”编译过程。随机 opaque object identifiers、最长近 600 token 的重复引用和 32 组 operation role query 会放大这个缺陷，但当前证据不能把失败单独归因于 Qwen hidden；A1.9 已证明在 oracle role segmentation 下，同一类 Qwen hidden 足以驱动结构化 core。

## 6. Oracle 替换归因

下表中的 oracle 只用于失败诊断，会改变部署接口，不是正式结果。

| 条件 | Trajectory | Final state | Answer |
| --- | ---: | ---: | ---: |
| 全预测 | `0.297363` | `0.409668` | `0.608887` |
| 全 oracle | `1.0` | `1.0` | `1.0` |
| 除 value 外全 oracle | `0.376953` | `0.544434` | `0.726074` |
| 除 source 外全 oracle | `0.414551` | `0.491211` | `0.656250` |
| 除 target 外全 oracle | `0.365234` | `0.453125` | `0.623535` |
| 除 family 外全 oracle | `0.816406` | `0.854004` | `0.931152` |
| 除 operation presence 外全 oracle | `0.985840` | `0.985840` | `0.992676` |
| 除 query 外全 oracle | `1.0` | `1.0` | `0.968750` |
| 只把 value+source+target+query 换成 oracle | `0.802734` | `0.840332` | `0.923340` |

因此 primary failure 是初始 value 与 source/target 的共同实体绑定；family 序列是 secondary but material；operation count 与 query 不是主因。全 oracle 恢复 `1.0` 同时确认 A1.19H core、数据 trajectory 与 evaluator 闭环没有失效。

## 7. 梯度信用审计

在 best checkpoint 的 16 条 train batch 上，只反传 state CE：

- value mapping logits 梯度范数为 `0.015382`，continuous payload 为 `0.130284`；
- entity presence、operation presence、family、source、target、query logits 梯度范数全部为 `0`；
- 完整 factorized loss 能给这些 logits 局部监督梯度；
- frozen core 没有梯度。

原因是阈值和 `argmax` 把离散预测变成控制后，执行结果对控制 logits 不可微。共享 reader 仍可能通过 value 路径得到间接梯度，但控制错误没有 execution-conditioned credit。当前 loss 因而优化“每个字段分别像标签”，而不是优化“一套程序执行后正确”。overfit32 可以靠记忆关闭这些局部标签；未见样本上的少量边际错误则在多实体、多步骤组合中迅速放大。

## 8. Gate 与路线判断

A1.20B 的 run-1 formal eligibility 失败。按预注册停线规则：

- 不生成 run-1 formal split cache，不把 validation 包装成 formal；
- 不运行 hidden/text causal suite；
- 不运行 run-2、run-3；
- 不进入 A1.21P 或 A1.22A；
- A1.19H generalized hybrid core 的正证据保留，但 V2-A 未通过。

如果未来继续验证，下一步不能是给当前配置增加 seed、step 或 hard re-embedding。需要先重做 Boundary 的实体表与程序生成机制，并让执行级目标能训练离散控制。合理候选包括分层 structured compiler、训练期可微或 straight-through 的受约束控制接口、显式先建 entity table 再解析 ordered operations，以及 sequence/joint consistency objective。任何方案都必须继续满足部署时无 oracle span/role、core 冻结或受控解冻、hard inference 重跑多 seed/causal 的合同。当前路线没有自动授权该重设计阶段，需要先重新立项。
