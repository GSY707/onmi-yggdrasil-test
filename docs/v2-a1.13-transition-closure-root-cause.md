# V2-A1.13：Transition × Closure 根因定位

日期：2026-07-16

状态：已完成；状态 Gate 显示联合臂 `3/3`，完整 Gate `1/3`

## 1. 要回答的问题

A1.12 已固定 exact-symbolic 输入，并分别恢复 entity-addressable state 与 operation-step cursor。若 BOTH 仍稳定失败，则匿名 binding 与内部时钟都不足以解释 Reasoner 故障，剩余候选主要是：通用 slot transition 没有足够的关系寻址归纳偏置，或 CE 目标没有把连续 latent state 约束到可递归复用的状态闭包。

A1.13 只拆这两个变量。共同合同固定为 A1.12-BOTH：三个 entity slot、五个 scratch slot、exact start/query/family/source/target、aligned cursor、`D=256`、逐步 state CE、独立 answer CE、batch、学习率、训练长度、seed、数据与 formal Gate 均不变。禁止 Qwen、Boundary、teacher state、hard re-embedding、COPY/SWAP 手写执行器和按长度专用参数。

## 2. 条件性 2×2

| transition | CE only | CE + soft prototype closure |
| --- | --- | --- |
| generic slot Transformer | A1.12-BOTH，复用三 seed 正式结果 | A1.13-GENERIC-CLOSURE |
| relation-addressed shared transition | A1.13-STRUCTURED-CE | 仅当两个单变量臂都失败时运行 A1.13-STRUCTURED-CLOSURE |

先运行 GENERIC-CLOSURE 与 STRUCTURED-CE。若至少一臂稳定 `3/3`，不运行 STRUCTURED-CLOSURE；若两臂均为 `0/3`，再运行 STRUCTURED-CLOSURE 判断是否为联合必要条件。任一臂出现 `1/3` 或 `2/3` 时记为 seed 不稳定，不作唯一归因。

## 3. 两个实验变量

### 3.1 Transition identity

generic 条件原样保留 A1.12-BOTH 的两层共享 self-attention / current-operation cross-attention / FFN block。

relation-addressed 条件仅替换 recurrent update：source/target register one-hot 从前三个 entity slot 进行确定性寻址，一个跨 family、register 与 step 共享的 MLP 接收 source content、target content 与 family embedding，输出 source/target proposal 和两个连续 write gate，再写回被寻址的 entity slots。它没有 COPY/SWAP 分支、没有离散 value 执行器，也不读取监督状态。五个 scratch slot、initial reader、state head 与 pooled answer head保持不变。

因此 STRUCTURED-CE 通过只能说明“显式关系寻址的 transition identity”是充分修复；不能把结论扩大成手写任务执行器成立。

### 3.2 Soft prototype closure objective

CE-only 条件保持 state CE + answer CE，各权重 `1.0`。

closure 条件只增加权重 `1.0` 的软 cosine loss。每个 entity register 的目标 prototype 由同一个 entity-initialization projection 对 `[current value one-hot; register one-hot]` 生成并 stop-gradient；预测 trajectory latent 接收梯度。prototype 不在 forward 中替换预测 state，不做 argmax、nearest-neighbor、hard re-embedding 或 teacher forcing。推理图与 CE-only 完全相同。

因此 GENERIC-CLOSURE 通过说明通用 transition 并非必要失败源，连续状态闭包目标本身就是充分修复。

## 4. 训练、Gate 与停止规则

两条首轮新臂先运行 length-balanced overfit32，T1–16 每长度 trajectory、final state、answer 必须全部 `1.0`，architecture integrity 与 data hash 必须通过。失败臂停止 formal；另一臂继续。

通过 overfit 的臂运行三组 fresh formal：data seed `20260721/22/23`，model seed `20261321/22/23`。优化器 AdamW，batch `32`，学习率 `3e-4`，最多 4000 steps，每 200 steps validation，patience 6，训练统一 16 recurrent steps。formal Gate 完全复用 A1.12；每臂必须 `3/3` 才算稳定通过。

正式 ordinary Gate 失败的 run 不运行 intervention；未运行不得记为 intervention failed。通过臂才运行结构反事实、disable recurrence 与错误 start-state permutation。

## 5. 归因规则

- GENERIC-CLOSURE `3/3`、STRUCTURED-CE `0/3`：主要根因是缺少连续 state closure objective；relation-addressed transition 不是必要修复。
- GENERIC-CLOSURE `0/3`、STRUCTURED-CE `3/3`：主要根因是 generic transition identity / relation addressing 不足；closure objective 不是必要修复。
- 两条单变量臂均 `3/3`：二者是替代性的充分修复；不能声称唯一根因。
- 两条单变量臂均 `0/3`、STRUCTURED-CLOSURE `3/3`：transition identity 与 closure objective 联合必要。
- 三条新臂均 `0/3`：这两个候选仍不足，A1.8 的额外 pointer supervision / answer coupling 是剩余差异；不得继续以小修 loss weight 救援。

本阶段不测试 full-text Boundary、Qwen、matched text-CoT、V2-A3/V2-A4 或 V2-B。
