# V2-A1.19H 可泛化混合 Core 实验记录

日期：2026-07-17

状态：已完成；H1/H2 formal 与 causal 均为 `3/3`，允许进入 A1.20B

## 1. 核心结论

A1.19H 通过。机器分类为 `generalized_hybrid_core_confirmed`。

本阶段把 A1.18B 的固定三寄存器正控制切换为 `S_t=(A_t,H_t)` 混合 core：opaque handle sidecar 只参与相等性寻址，连续 payload 承载状态和语义更新；entity initializer、transition、state head 与 query-coupled answer 均跨实体、跨 step 共享。部署模型不包含训练辅助头，也不存在 handle embedding、固定前三槽语义或 COPY/SWAP 专用执行分支。

H1 在固定 `N=3` 下删除 register identity 与 slot index 的绑定；H2 进一步在 `N=2,3,4` 上训练，并把 `N=5` 与 heldout relation 留作正式外推。两个子门的 overfit32、三个 fresh seed formal 和 formal 后 causal intervention 全部通过。

这证明当前混合 core 可以在受控 exact-symbolic 状态机上跨 slot 映射、opaque handle、程序长度、关系组合和实体数量泛化。它仍不是完整 V2-A：full-text role discovery、真实 Qwen Boundary、matched text-CoT Pareto、第二任务族与自然语言 audit 都尚未验证。

## 2. 冻结架构与训练合同

运行状态分为两层：

- `A_t` 只保存 opaque identity/address sidecar；handle 没有语义 embedding，只能通过相等比较选择 source、target 和 query entity；
- `H_t` 保存连续 entity payload 与 scratch workspace；实际状态变化由唯一 shared transition 完成；
- start value initializer、entity seed、transition、state head 和 answer readout 都不绑定实体名称或物理 slot；
- 正式答案只读取最终 queried entity 的 shared state head；answer CE 权重固定为 `0`；
- 训练期保留每步 set-equivariant global-context state auxiliary、state CE 和 soft closure；formal 前物理删除 `training_auxiliary_head.*`；
- 固定 FP32、AdamW、batch `32`、T1–16 均衡训练和 `4000` step formal budget，不根据早期满分提前停止。

H2 的训练实体数为 `N=2,3,4`，heldout 实体数为 `N=5`。每条记录使用随机 opaque lexical object name、随机 semantic-to-physical slot 映射与随机整数 handle；三组数据 seed 互相排除 fingerprint。heldout relation 为每条记录首个 opaque object 到最后一个 opaque object 的 COPY 关系，该关系不进入 supported split。

## 3. 执行过程中的方法修正

本阶段出现三项实现/实验方法缺陷，但都在正式证据形成前被停止并修正。

第一版 H2 使用固定 `entity_0...` 名称，导致小 `N/T` 组合的有限支持无法满足跨 run fingerprint 排除。该数据设计不能支撑三个独立 formal run，因此删除未训练数据并直接切换为逐记录随机 opaque lexical identifier，没有保留兼容路径。

第一版 H2 overfit32 selector 按排序后的前 32 个 cell 取样，遗漏 `N=4`。模型在已选 cell 上全为 `1.0`，但 `all_training_entity_counts_present` Gate 失败。该结果不被当作架构失败；selector 改为循环覆盖 `N=2,3,4` 与 T1–16 后从 fresh initialization 重跑，严格 overfit Gate 通过。

H2 run-3 初次训练时 GPU 功率长期处于个位数。分析发现每步都在 Python 循环中把数百个标量写入 CUDA tensor，并在每个 recurrent step 用 `if torch.any(CUDA tensor)` 做 source/target 地址检查，造成大量 CPU/GPU 同步。该半成品 checkpoint 被删除，训练管线直接切换为：

- 全训练集与验证集一次性在 CPU 编码并完成严格地址校验；
- tensor cache 一次性搬到 GPU，训练步只执行 `index_select`；
- 完整采样序列预生成，保持旧 RNG 顺序；
- 所有 operation shape 固定为 T16；
- source/target routing weight 与 family embedding 在 forward 中一次性预计算；
- 每步不再把 loss/gradient norm 同步回 CPU，只在 validation interval 记录；
- formal split 也只编码一次并复用 GPU cache。

60-step 同初始化、同 batch 序列、同 FP32/AdamW/loss 对照中，旧管线为 `33.0679s`，新管线为 `3.0778s`，加速 `10.744×`；最终 loss 差为 `0`，所有参数的最大绝对差为 `0`。优化后的 run-1 checkpoint 全 split 回归与旧 formal JSON 逐字段相同。run-3 正式 4000-step 训练为 `155.52s`、`25.72 step/s`；旧 run-1 为 `893.24s`。

## 5. 证据边界与下一阶段

A1.19H 关闭的是 generalized hybrid core，而不是完整推理介质。当前输入仍是 exact-symbolic operation/state；Boundary 尚未从完整文本自主发现 source、target、query、relation、value 与 control。训练仍使用可执行程序生成的逐步完整状态 target；这符合当前白皮书允许的 teacher/trace 合同，但其生成成本和开放任务覆盖需要在后续 Pareto 中报告。

下一阶段唯一允许执行 A1.20B：冻结已经通过的 A1.19H core，使用完整 Qwen hidden 训练 learned full-text Boundary。不得重新引入 oracle span mask、role tensor、hard re-embedding 诊断补丁或任务专用执行分支。Boundary 必须先独立通过 pointer/role/handle geometry 与 task formal，再允许短程联合；若任一正式 Gate 失败，停止 A1.21P/A1.22A。
