# V2-A1.17：Objective × Initialization 配对审计

日期：2026-07-17

状态：已完成；两条 coupled 臂 state/full 均为 `0/3`，配对根因已定位但架构未通过

## 1. 为什么需要配对审计

A1.13-STRUCTURED-CLOSURE 使用 model seed `20261321/22/23`，state Gate 为 `3/3`。A1.15 与 A1.16 为测试独立 formal 稳定性，分别使用新的 `20261521/22/23` 与 `20261621/22/23`。如果后两阶段失败，证据能否定当前配置的跨初始化稳定性，却不能把差异唯一归因于 answer readout 或 answer loss，因为 objective 与 initialization 同时改变。

A1.17 只做配对因果审计：对 A1.13 的三个 data/model seed fresh 重跑 query-coupled 条件。实现初始化顺序保证 relation transition、entity initialization、state head 等共享参数在同 numeric seed 下与 A1.13 一致；独立 answer head 先按相同顺序初始化后再删除，不改变共享参数的随机流。

## 2. 配对矩阵

| paired model seed | independent pooled answer + CE | query-coupled + answer CE | query-coupled + no answer CE |
| --- | --- | --- | --- |
| `20261321/22/23` | 复用 A1.13-STRUCTURED-CLOSURE | A1.17-COUPLED-CE | A1.17-COUPLED-NOCE |

data seed 固定为 `20260721/22/23`。除 answer readout 与对应 loss 外，数据、模型共享参数初始化、训练、early-stop、预算、checkpoint scoring 与 formal Gate 全部相同。所有新 run 都从 step 1 fresh 训练，不加载 A1.13 checkpoint。

先运行 COUPLED-CE 三个 paired seed。若 full Gate `3/3`，已经足以把新 seed failure 定位为初始化盆地问题，不再运行 COUPLED-NOCE；否则再运行 COUPLED-NOCE，拆分 query coupling 与冗余 CE。

## 3. 判定

- COUPLED-CE state `0/3`、COUPLED-NOCE full `3/3`：冗余 answer CE 是配对条件下的直接失败源。
- 两条 query-coupled 臂均 full/state `3/3`，但新 seed formal 失败：主要问题是初始化盆地稳定性，不是 readout 接线。
- 两条 query-coupled 臂均 state `0/3`：独立 pooled answer objective 虽然读出不稳定，却可能提供了 transition 学习所需的全局辅助梯度；删除旁路同时破坏优化。
- 任一臂为 `1/3` 或 `2/3`：objective 与 initialization 存在交互，不能作唯一根因结论。

paired audit 只用于归因，不替代新 seed formal 的稳定性 Gate。即使配对通过，只要新 seed formal 非 `3/3`，当前核心仍不能作为稳定架构成立。

## 4. 完整性与正式结果

A1.15 与 A1.16 的 fresh-seed state Gate 均为 `0/3`，触发条件成立。assessment 除核对 model/data seed 外，还用相同 numeric seed 重新构造 A1.13 independent 与 coupled 模型；删除 `answer_head` 后的全部共享 state-dict tensor 名称一致、数值逐 tensor 位相等，三个 seed 均通过。因此以下差异不是“seed 编号相同但共享初始化实际不同”。

| paired arm | state Gate | full Gate | short trajectory | relation T16 | supported OOD T24 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1.13 independent pooled answer + CE | `3/3` | `1/3` | `1.0`（三 run） | `0.992188–1.0` | state Gate 通过 |
| A1.17 query-coupled + answer CE | `0/3` | `0/3` | 约 `0.01` | `0` | `0` |
| A1.17 query-coupled + no answer CE | `0/3` | `0/3` | `0.0052–0.0182` | `0` | `0` |

所有 coupled run 的 answer-state prediction consistency 均为 `1.0`，所以它们确实消除了答案与预测 state 的接线脱钩；失败发生在 state transition 根本没有学会。ordinary formal 全失败，按停止规则没有运行干预。

机器分类为 `independent_answer_auxiliary_gradient_required`，`root_cause_localized=true`，但 `architecture_validated=false`。严格含义是：在当前 relation-addressed transition + soft closure + end-to-end objective 中，独立 `workspace mean → answer head` 的 answer CE 提供了让 state 算法进入可学习盆地的全局辅助梯度；删除该目标，无论是否在 shared queried-state logits 上保留重复 answer CE，三个原本成功的共享初始化都无法启动状态学习。与此同时 A1.13 的 full Gate 仅 `1/3`，说明这个辅助路径又不是可靠的最终答案接口。

这不是“答案旁路应该保留”的架构正证据，而是一个训练目标悖论：当前系统依赖一个不可作为最终因果输出的旁路来学会 state。已排除的主要解释包括 binding、cursor、单独增加训练预算、坏初始化和重复 answer CE 单因素；未区分的是 pooled 全局梯度、query-answer 标签和额外 head 参数中哪一项提供了关键优化作用。
