# V2-A1.9：冻结 Qwen hidden 边界

日期：2026-07-15

状态：已完成；三个预注册 run 的 cache audit、formal 与 hidden causal Gate 全部通过

证据范围：oracle role span 分段的 frozen Qwen3.5-2B hidden → frozen A1.8 structured continuous core

## 1. 核心问题

A1.8 已证明 content-only state slots、独立 register address keys、唯一 shared transition、共享 state/answer head 和 prototype closure 组成的结构化连续核心，在 T1–16 均衡随机深度训练后可稳定推进到 T24 Gate。A1.9 不再修改这个核心，只回答：冻结 Qwen 的上下文化 hidden states 能否通过窄边界映射，进入 A1.8 已建立的 value、family 和 register 语义坐标，并保持组合、长程和因果忠实性。

A1.9 是 boundary positive control，不是白皮书目标架构的完整实现。它保留 oracle character spans、显式三寄存器结构和 COPY/SWAP 合成任务；不覆盖 learned latent queries 自主读取完整文本、匿名 K-slot workspace、通用 recurrent Transformer reasoner、matched text-CoT Pareto、audit、MoE 或多模态。

## 2. 冻结合同

每个正式 run 绑定一个已经通过 A1.8 的 `best.pt`。以下参数全部冻结：

- Qwen3.5-2B 文本塔及其固定 revision；
- A1.8 value embeddings/prototypes、family embeddings、register keys；
- A1.8 shared transition 与 shared state/answer head；
- closure 权重 `1.0` 和 T1–16 均衡长度训练合同。

唯一可训练模块为三个边界映射：

- `value_adapter`：初始 value span hidden → frozen value prototype space；
- `family_adapter`：COPY/SWAP span hidden → frozen family embedding space；
- `register_adapter`：source、target、query register span hidden → frozen register-key space。

source、target 和 query 必须共享同一个 `register_adapter`。query 只允许在递归结束后选择最终 register slot；不得写入 state、transition 或独立答案头。最终答案必须严格等于 frozen shared state head 在最终 query slot 上的 logits。

禁止 full-source mean/cross-attention/source reread、answer/query bypass、新答案头、teacher state、hard re-embed、oracle reset、Qwen/core 解冻和旧 A1.6 compatibility wrapper。

## 3. 数据与 cache

A1.9 直接复用三组已审计的 A1.8 records 和 fingerprint split，但生成独立 schema 的 Qwen cache。训练继续覆盖 T1–16 并在 batch 内严格均衡；正式评测保持：

- short regression：T1–6；
- supported/relation in-range：T8/T12/T16；
- supported/relation OOD：T20/T24，T32 只作诊断；
- causal core：T2/T3/T4。

cache 只保存 masked-mean pooled role hidden，不保存 full-source hidden。每条记录必须保存三个初始 value、query、逐步 family/source/target、operation offsets、fingerprint、token length 和 example id。manifest 必须固定 Qwen model/revision、FP16、last hidden layer、无静默截断、oracle span segmentation 和 `full_source_saved=false`。

cache audit 必须确认数据/cache fingerprint 一一对应、split 数量一致、hidden 全部 finite、宽度一致、operation 数量正确、跨 split overlap 为零、没有 full-source tensor，且数据 manifest 已通过 A1.8 audit。

## 4. 训练合同

先执行覆盖 T1–16 的 length-balanced overfit32。同一 32 条只作 fit-only 正控制，不作为 heldout 证据。overfit32 必须同时达到：

- value/family/register/query mapping accuracy `1.0`；
- source/target pointer accuracy `1.0`；
- trajectory、final state、final answer exact `1.0`；
- answer/state logits identity 精确成立；
- core 全参数 `requires_grad=false` 且训练前后 hash 不变。

overfit32 失败时停止，不运行正式实验。

正式训练使用三个预注册 run：

| run | A1.8 data seed | A1.8 core seed | A1.9 adapter seed |
|---|---:|---:|---:|
| 1 | `20260721` | `20260821` | `20260921` |
| 2 | `20260722` | `20260822` | `20260922` |
| 3 | `20260723` | `20260823` | `20260923` |

loss 由 frozen-prototype regression/classification、完整 trajectory state、source/target pointer、final answer 和 closure 组成。best checkpoint 优先选择 validation 最差长度 trajectory，再考虑 aggregate trajectory 与 boundary mapping；不得按普通平均值掩盖弱长度。

## 5. 正式 Gate

三个 run 必须分别满足：

1. short T1–6 每个长度 trajectory full exact ≥ `0.95`；
2. supported T8/T12/T16 每个长度 ≥ `0.95`；
3. relation T8/T12/T16 每个长度 ≥ `0.95`；
4. supported T20/T24 每个长度 ≥ `0.90`；
5. relation T20/T24 每个长度 ≥ `0.90`；
6. causal-free trajectory ≥ `0.95`；
7. value/family/register/query mapping 与 source/target pointer aggregate 均 ≥ `0.995`；
8. answer/state logits identity、prototype non-collapse、core frozen hash 和 architecture integrity 全部通过。

T32 只作诊断，不参与总 Gate。

## 6. hidden 因果 Gate

Qwen span hidden 是上下文化表征，单个 span 可能携带超出局部 token 的样本信息。因此普通准确率不能排除身份捷径。正式 Gate 通过后才运行以下干预：

- `prefix`：截断 operation hidden，按前缀重新计算 oracle；
- `operation replacement`：用其他样本的完整 family/source/target hidden 替换单步并重新计算 oracle；
- `deletion`：删除单步 hidden 并重新计算 oracle；
- `operation shuffle`：重排 hidden steps 并重新计算 oracle；
- `query swap`：只替换 query hidden；完整 trajectory 必须保持不变，答案必须跟随新的 query register；
- `same-answer/different-trajectory`：构造最终答案不变但中间轨迹改变的 role-hidden 混合反事实，模型必须跟随重新计算的完整轨迹；
- `no hidden` 与 independent role shuffle：保持原 oracle 时必须产生显著破坏，不能由 bias 恢复任务。

prefix trajectory ≥ `0.99`；replacement、deletion、operation shuffle、query-swap answer 和 same-answer trajectory 均 ≥ `0.95`；query-swap trajectory invariance ≥ `0.99`。只在 oracle 确实改变的必要样本上计算破坏率，并同时报告对新 oracle 的跟随率与对旧 oracle 的保留率。

## 7. 结果边界与停止规则

若 overfit32 失败，优先检查 cache/span/冻结连接，不修改 core。若 ordinary 通过而 relation 失败，判定旧 A1.5 的 operation-composition binding 问题仍存在。若 relation 通过而长程失败，在相同 A1.8 core 已通过的前提下归因 boundary output 随上下文或长度漂移。若普通 Gate 通过但 hidden intervention 失败，判定存在身份或上下文捷径，A1.9 仍失败。

只有三组 data/cache/formal/causal、跨 run fingerprint、core frozen hash 和成本 artifact 全部通过，才能声称“oracle-role-segmented frozen Qwen hidden boundary 可驱动 frozen structured continuous core”。即使通过，也不能声称匿名 workspace、自由文本解析、目标 recurrent reasoner、V2-A Pareto 或完整 V2 成立。

## 8. 正式结果

length-balanced overfit32 在 step `100` 达到 value/family/register/query mapping、source/target pointer、trajectory 和 final answer 全部 `1.0`，并在 step `200` 按合同停止。三个正式 run 的 data/core/adapter seed 严格采用预注册组合；每组 cache 均含 `22,784` 条记录，三组 cache fingerprint 两两 overlap 为 `0`，所有 cache audit 均通过。

三个 run 的正式结果为：

| 指标 | 三 run 最低值 |
| --- | ---: |
| short T1–6 trajectory | `1.0` |
| supported T16 trajectory | `1.0` |
| relation T16 trajectory | `0.996094` |
| supported T24 trajectory | `1.0` |
| relation T24 trajectory | `1.0` |
| supported T32 trajectory（诊断） | `0.996094` |
| relation T32 trajectory（诊断） | `1.0` |
| value/family/register/query mapping | `1.0` |

run 1/2 在 step `400` 停止，run 3 在 step `800` 停止。run 3 的 validation T16 trajectory 在 step `400` 短暂降到 `0.992188`，随后恢复；正式 best checkpoint 为 step `200`，所有正式 Gate 通过。这是轻微、可恢复的边界几何漂移信号，不构成失败，但说明后续 learned boundary 不能只看最终平均准确率。

三 run 合计训练 `204,800` examples、`1,740,800` latent transitions，用时 `825.66` 秒。每个 run 的 A1.8 core 全参数 hash 在训练前后完全不变；Qwen 与 core 均冻结，唯一 trainable 参数为 `1,573,632` 个 boundary adapter 参数。

## 9. hidden 因果结果

三个 run 的 prefix、operation replacement、deletion、operation shuffle、query swap 和 same-answer/different-trajectory 全部以 `1.0` 跟随重新计算的 oracle。query swap 保持完整 trajectory `1.0`，且 final answer 对新 query 的准确率为 `1.0`；replacement 对旧 trajectory 的保留率为 `0`，same-answer 反事实对旧 trajectory 的保留率为 `0`。no-hidden 与 independent role shuffle 的 trajectory full exact 在三个 run 中均为 `0`。

因此现有结果不仅表明 adapter 能拟合普通样本，也表明模型实际依赖输入的 role hidden，且在所测试反事实中没有依靠答案、样本身份或原始轨迹捷径恢复结果。

## 10. 成本与口径

RTX 4070 Laptop GPU 上，三组 Qwen role cache 编码共计 `3,451.30` 秒，峰值 allocated memory 为 `5,183,613,440` bytes，cache 总磁盘占用 `9,177,138,012` bytes。该计时从模型加载完成后开始，**不包含 Qwen/tokenizer 首次加载时间**。

run 1 的 cached adapter/core benchmark 在 batch `128` 下为 `0.08738` 秒/训练 step、约 `12,451` transitions/s；T16 cached inference 为 `0.01986` 秒/batch，峰值 allocated memory `109,217,280` bytes。这里只测预计算 role hidden 后的 boundary/core，不是在线端到端延迟，也没有与 text-CoT 做 matched Pareto；`use_cache=false`，没有 KV cache 收益。

## 11. 判定与下一步

**A1.9 总 Gate 为 3/3 passed。**可以成立的结论是：oracle-role-segmented frozen Qwen3.5-2B hidden 可通过窄边界映射，因果忠实地驱动 frozen A1.8 structured continuous core，并保持到 T24 正式 Gate 和 T32 诊断。

不能成立的结论是：模型已经学会从完整自然语言自主发现 role、匿名 K-slot workspace 已成立、通用 recurrent Transformer reasoner 已成立，或 V2-A 已相对 matched text-CoT 形成质量—成本 Pareto。A1.9 仍提供 oracle character spans、显式 value/family/register 类型和三寄存器状态机，任务也只有 COPY/SWAP。

下一阶段应执行 A1.10A learned boundary：保持 Qwen、A1.8 core、任务、训练长度、Gate 和 adapter 容量级别不变，只删除 oracle role span 分段，令 learned role queries 从完整 frozen Qwen token hidden 中提取相同的 typed boundary 输入。A1.10A 通过前不同时引入匿名 workspace、新 reasoner、matched Pareto、V2-A3/V2-A4 或 V2-B，以免重新混合核心变量和附加机制。

后续状态（2026-07-16）：用户明确决定把 oracle span 删除、匿名 K-slot workspace 和通用 recurrent reasoner 合并到 A1.10；上述单变量建议因此只保留为 A1.9 完成时的实验设计意见，不再是当前执行路线。联合 A1.10 已以正式 Gate `0/3` 结束，当前下一步是 A1.11 正交故障定位，见 `docs/v2-a1.10-anonymous-workspace.md`。
