# V2-A1.20C 分层编译器与执行信用修复实验记录

日期：2026-07-17

状态：已停止；目标臂 `hierarchical + straight-through` 的 overfit32 Gate 失败，未运行完整 2×2 validation matrix、formal/causal、A1.21P 或 A1.22A

## 1. 结论

A1.20C 没有通过，但把 A1.20B 的宽泛 Boundary 故障进一步收窄了。分层编译器能够从完整 Qwen hidden 中准确定位实体名、实体值、每步 family/source/target 和 query token：best checkpoint 的所有 anchor sequence exact 都是 `1.0`。训练期 straight-through bridge 也保持了严格 hard forward，state/answer logit 的最大差均为 `0`，冻结 A1.19H core 的 hash 不变。

目标臂仍未通过最小 overfit32 Gate。固定 5000 step 后，best checkpoint 位于 step 4800；32 条样本的 aggregate trajectory/final-state/state-token/answer 为 `0.875/0.90625/0.964474/1.0`，mapping minimum 为 `0.90625`。四条 `N=4` 样本仍有 entity count、operation count 或受 entity mask 影响的 pointer 错误，所以最差 cell mapping/trajectory 仍为 `0/0`。final answer 全对不能替代内部程序与状态 Gate。

失败的一级原因不是 token role discovery，也不是 frozen core 容量，而是当前执行信用修复仍不完整，并且两个训练目标在接近收敛时直接冲突。在 best checkpoint 的同一 overfit32 batch 上，`state CE` 与其余 local mapping、payload、anchor loss 的全参数梯度 cosine 为 `-0.7366`；entity path 为 `-0.9680`，presence heads 为 `-0.9944`，shared source path 为 `-0.9565`。固定 `3e-4` 学习率又使 total loss 从 step 4800 的 `0.2429` 回升到 step 5000 的 `0.6103`。

因此 A1.20C 的机器分类为 `anchor_localization_solved_but_execution_objectives_conflict`。A1.19H generalized hybrid core 的正证据继续保留，但 full-text Boundary 尚未成立，V2-A 仍未通过。

## 2. 实验合同

A1.20C 冻结 A1.19H-H2 run-1 core，并复用 A1.20B 已审计的完整 Qwen3.5-2B last-hidden cache。Boundary 前向仍只能接收 `source_hidden` 与 `source_attention_mask`；训练期 token anchor target 不进入模型前向，部署时也不需要 tokenizer offset、oracle span、role tensor、entity mask、operation mask 或答案 metadata。

预注册的 2×2 主动变量为：

| 维度 | 对照 | 修复候选 |
| --- | --- | --- |
| compiler | A1.20B flat typed-query reader | hierarchical entity-table-first compiler |
| execution credit | hard local controls | straight-through hard-forward/soft-backward bridge |

`flat + hard-local` 必须与 A1.20B 精确等价。分层编译器先从 full source 建立实体表，再分别读取 ordered operation 的 family/source/target 和 query；token 位置只作为训练监督。straight-through 模式的部署前向继续使用 hard prefix mask、hard family 与 hard pointer，训练反向则使用 soft surrogate 驱动冻结 core。

目标臂只有在 overfit32 的全部 cell mapping、trajectory、final state、answer 和 hierarchical anchor sequence 都为 `1.0` 时，才有资格运行同 seed 2×2 heldout validation。heldout eligibility 的 minimum-cell mapping/trajectory/answer 与 aggregate state-token 必须全部不低于 `0.995`，之后才允许三 seed formal/causal。目标臂任何前置 Gate 失败都停止 A1.21P/A1.22A。

## 3. 实现、审计与吞吐

新增实现包括：

- 训练专用 token anchor target 的生成与 no-forward-input audit；
- 与 A1.20B 精确等价的 flat compiler wrapper；
- entity-table-first hierarchical compiler；
- hard-forward/soft-backward 的 family、source、target、query、entity/operation mask 执行桥；
- overfit/formal eligibility、hard-forward equivalence、core hash 和 anchor exact Gate；
- 实际 checkpoint 的 state-vs-local 梯度夹角诊断。

overfit32 与 run-1 supervision audit 均通过。overfit supervision 为 train/validation 各 32 条；run-1 为 train 16,384、validation 2,048 条。审计确认 token offset 与语义角色一致、所有 target shape/range 合法、forward input 仍只有 full source hidden/mask。

4 项 A1.20C 回归测试通过，覆盖 anchor target、flat-hard 等价、no-oracle forward、ST hard-forward 等价和离散控制梯度恢复。2-step CUDA smoke 的 state/answer hard-forward 最大差均为 `0`，core 完整性通过。

目标臂约 `7.442M` 可训练 Boundary 参数，冻结 core 约 `1.322M`。5000-step overfit32 总耗时 `1178.79s`，平均 `4.2416 step/s`；训练过程中 GPU 可达到约 `60W` 和高利用率。该轮不重复 Qwen 编码，性能已不再是 Gate 失败主因。

## 4. 目标臂 overfit32 结果

目标臂使用 reader/data/core seed `20262011/20261951/20261961`，从 fresh Boundary 初始化，以 full-batch 32、固定学习率 `3e-4` 训练 5000 step，每 100 step 完整评估。

| 指标 | best step 4800 | Gate |
| --- | ---: | ---: |
| anchor all-sequence exact | `1.0` | `1.0` |
| trajectory full exact | `0.875` | `1.0` |
| final state full exact | `0.90625` | `1.0` |
| state token accuracy | `0.964474` | `1.0` |
| final answer accuracy | `1.0` | `1.0` |
| mapping minimum | `0.90625` | `1.0` |
| value/family mapping | `1.0/1.0` | `1.0/1.0` |
| source/target/query mapping | `0.959559/0.981618/0.96875` | `1.0/1.0/1.0` |
| entity/operation presence | `0.90625/0.96875` | `1.0/1.0` |
| hard-forward state/answer delta | `0/0` | `≤1e-6` |

四条失败样本全部位于 `N=4`：

| Cell | 主要错误 | Trajectory | Final state | Answer |
| --- | --- | ---: | ---: | ---: |
| `N4-T5` | entity presence；source/target 随后受损 | `0` | `0` | `1` |

训练曲线不是稳定欠拟合。step 1400 时 anchors 已全对，aggregate value/source/target 为 `0.8737/0.9449/0.9228`；step 4800 又升到 `1.0/0.9596/0.9816`。但 step 4900 和 5000 显著退化，说明固定学习率下存在离散边界震荡。

## 5. 根因

### 5.1 结构化定位已经解决

best checkpoint 的 entity-name、entity-value、operation-role、query anchor token 与 sequence 指标全部为 `1.0`。因此 A1.20B 的“flat reader 无法稳定定位重复实体/长程序角色”已被分层编译器在 fit-only 条件下修复。不能再把这次 overfit 失败归因于 source token 找不到。

### 5.2 pointer-validity 仍经过硬布尔断点

local source/target/query CE 直接训练未执行 entity-mask 的 pointer logits；实际执行前，pointer logits 会按预测的 hard entity mask 再遮罩。当前 ST bridge 对 family/pointer one-hot 和传入 core 的 entity/operation mask 提供 soft backward，但 pointer softmax 的“哪些实体允许参与”集合仍由 `predicted_entity_mask` 布尔张量决定。

这解释了 step 4800 的表面矛盾：query CE 只有约 `5.4e-7`，执行 query accuracy 仍为 `0.96875`；三条 entity-count 错误会同时改变 source/target/query 的有效候选集合。局部 pointer loss 与实际执行接口并不完全同构。

### 5.3 state 与 local compiler objective 发生强负梯度冲突

实际 best checkpoint 的梯度审计为：

| 参数组 | state gradient norm | local gradient norm | Cosine |
| --- | ---: | ---: | ---: |
| 全部 Boundary | `0.7344` | `0.5352` | `-0.7366` |
| entity path | `0.3626` | `0.3488` | `-0.9680` |
| presence heads | `0.2013` | `0.2014` | `-0.9944` |
| shared source path | `0.3593` | `0.3398` | `-0.9565` |
| operation path | `0.0741` | `0.0558` | `-0.3072` |
| pointer heads | `0.0461` | `0.0297` | `-0.2894` |

这不是泛泛的“多任务可能冲突”，而是已在真实 checkpoint 上测得的近反向梯度。straight-through 成功恢复了执行级梯度，但未经约束地把它与 local compiler 梯度相加，导致它在最需要稳定 count/mask 的阶段反而破坏 local exact。

### 5.4 answer 与内部状态继续脱钩

step 4800 的 32 条 answer 全对，但 trajectory 只有 28 条、final state 只有 29 条正确；四条失败 cell 的 answer 也全部正确。A1.20C 因此保留了严格内部状态 Gate，没有把 answer `1.0` 包装成机制通过。

## 6. Gate 与下一修复边界

A1.20C 目标臂 overfit32 Gate 失败。按合同：

- 不运行另外三个 2×2 正式训练臂；
- 不运行 heldout validation matrix；
- 不运行三 seed formal 或 causal suite；
- 不运行 A1.21P matched Pareto；
- 不运行 A1.22A natural-language audit。

下一次尝试不能只是增加 seed 或按同一固定学习率延长训练。最小修复必须同时覆盖三个边界：

1. 把 entity count 与 pointer validity 联合连续化，同时保持 hard forward；合理形式是显式 categorical count + ST prefix mask，或对 hard mask 做 soft-validity 加权并在归一化前保留到 count logits 的梯度。
2. 把 compiler fitting 与 execution fitting 分阶段，或对负梯度做明确投影；不能继续从 step 1 等权相加 state CE 和全部 local/anchor loss。
3. 在 joint 阶段使用学习率衰减，并在后期提高 validation/checkpoint 频率，防止 step 4800→5000 的离散退化。

这些是下一修复阶段的立项边界，不是本轮已验证方案。任何修复都必须重新从 fresh initialization 通过 overfit32，再恢复原 2×2 与 formal/causal 顺序。
