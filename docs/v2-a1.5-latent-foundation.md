# Project-Yggdrasil V2-A1.5：潜空间建立与递归正控制

日期：2026-07-13  
证据范围：A1.5 独立 schema、P0 结构化正控制、P1 Qwen hidden 接口 formal surrogate、P2 learned-slot formal surrogate、matched visible text baseline

## 总体判定

本轮没有通过 A1.5 Gate，但已经把旧 V2-A2 的混杂因素拆开了：

1. **P0 结构化 recurrent core 可以被训练出来。**在 32-example overfit 中，最终答案与每步 full-state exact 都达到 `1.0`；在 4096 条结构化训练、256 条验证和 256 条普通 test 上，best checkpoint 的 final/state exact 也是 `1.0/1.0`。
2. **这不能推出 latent 接口成立。**相同 P0 core 在未见过的 `swap->copy` composition split 上只有 final `0.2734`、state full exact `0`；因此递归单元的局部执行能力与组合泛化被明确区分开了。
3. **长度外推的答案可以成立，但逐步状态仍不稳。**5–6 步 length-heldout 的 final answer 为 `1.0`，state token accuracy `0.9186`，state full exact `0.2266`。这说明答案头可能学会了受限模板的结果映射，不能只看 final answer 宣称状态轨迹正确。
4. **P1 hidden→latent 接口在 4096 条缓存上通过 warm-up 与联合训练。**验证集初始程序要素重建在 warm-up step 1000 达到 `1.0`，best checkpoint（step 2500）重新加载后 final/state 均为 `1.0`；此前 64 条 small probe 的失败是 underfit 诊断，不再被写成架构失败。
5. **P2 learned K=8 workspace 可以在 ordinary split 学到状态，但 composition 仍失败。**best checkpoint 的 ordinary test final/state 为 `1.0/1.0`，composition 为 `0.2773/0`，length 为 `1.0/0.6484`；transition-delta shuffle 和截短会破坏 state，same-answer shuffle 在 composition 上暴露样本身份依赖。

因此，本轮的分层结论是：

> “recurrent architecture 完全不能工作”已被 P0 正控制否定；“Qwen hidden 已形成信息保真的 latent workspace”尚未被证明；当前主要失败位于 operation-conditioning 的组合泛化、hidden→latent 信息保真与逐步状态可靠性，而不是再做小规模 K/T sweep。

## 1. 独立实验合同

本轮没有沿用 `yggdrasil.v2-a.symbolic-state-machine.v4` 的 Gate 结论，新增 schema：

```
yggdrasil.v2-a1.5.symbolic-state-machine.v1
```

任务仍为三寄存器 `amber/cobalt/jade` 的 `SWAP`/`COPY` 状态机，但合同做了四项关键修正：

- train 覆盖 1–4 步；普通 validation/test 与 composition-heldout 都是 2–4 步，长度范围完全匹配；length-heldout 是 5–6 步，且不包含 `swap->copy`，避免 composition 与长度混杂。
- 每条样本逐步保存 `operation_spans`、`operation_mask`、结构化 token 序列和状态轨迹；每个核心评测样本都做“把任意一步替换为 `NOOP`”的反事实检查，要求每一步都会改变最终 queried answer。
- split 生成按程序长度和 operation family 配额控制，当前大规模 manifest 为 train `4096`、validation/test/composition/length 各 `256`，所有 split 的必要步骤率为 `1.0`，跨 split fingerprint overlap 为 `0`。
- 所有 split 都提供 `0-step`、`prefix-1`、`prefix-2`、`majority`、`initial-query` 和完整符号执行 `oracle` 弱基线；这些基线不读取模型答案字段。

数据入口和最终 manifest：

- `experiments/v2_a1_5_latent_foundation.py prepare-data`
- `artifacts/v2-a/a1_5/data-large/manifest.json`

大规模数据的长度/操作配额为：

| split | 长度 | examples | copy/swap 操作数 | composition tag 比例 |
|---|---:|---:|---:|---:|
| train | 1/2/3/4 各 1024 | 4096 | 4096 / 6144 | 0 |
| validation | 2/3/4 各约 85 | 256 | 256 / 511 | 0 |
| test | 2/3/4 各约 85 | 256 | 256 / 511 | 0 |
| composition-heldout | 2/3/4 各约 85 | 256 | 256 / 511 | 1 |
| length-heldout | 5/6 各 128 | 256 | 256 / 1152 | 0 |

length split 中 operation family 数量不是 1:1，这是“每一步都必须必要”与无 `swap->copy` 约束共同造成的可解释限制；它仍同时包含两类 operation，且不混入 composition tag。

## 2. P0：结构化输入正控制

### 2.1 实现

P0 使用 `D_latent=256`、3 个显式 register slots 加 1 个 query/control slot。每个程序操作执行一次 transition，`T=program_length`，transition 权重在所有步骤完全共享。单个 shared transition 包含：

```
pre-norm slot self-attention
-> 当前 operation token 的 cross-attention
-> Dense FFN
-> 直接 residual scale（初始 0.1）
```

没有绝对 step embedding、sigmoid 饱和 gate、teacher trace、答案旁路或 verifier-RL。最终答案头只读取最终 query/control latent slot；每个有效程序步骤都用 state CE 解码三个 register。

### 2.4 P0 因果干预

干预由 `experiments/v2_a1_5_latent_foundation.py p0-intervene` 生成，完整结果在 `artifacts/v2-a/a1_5/p0-final/results.json` 的 `causal_interventions` 中。这里的 `final_answer_accuracy` 是相对于被修改轨迹的符号 oracle；`changed_prediction_rate` 记录模型预测是否随干预改变。

| split/干预 | counterfactual final accuracy | changed prediction rate | 解释 |
|---|---:|---:|---|
| test / replace one step with NOOP | `0.0965` | `0.2947` | 正常轨迹学会后，替换后的状态映射仍不稳 |
| test / delete one step | `0.1095` | `0.2920` | 删除能破坏答案，但不是可靠的逐步重算 |
| test / half trajectory | `0.6641` | `0.0625` | 与 prefix-2 baseline 接近，普通短程序不适合只看 half |
| test / disable transition delta | `0.1172` | — | 禁止 delta 后接近随机，说明正常 test 确实用了 transition |
| composition / replace NOOP | `0.3677` | `0.2868` | 未见 bigram 上没有稳定的状态重算 |
| composition / half trajectory | `0.3945` | `0.4570` | 轨迹缩短会破坏，但正常 composition 本身已失败 |
| length / replace NOOP | `0.0348` | `0.1634` | 长程序的最终答案对单步变化敏感，但逐步 state exact 仍低 |
| length / half trajectory | `0.0039` | `0.0039` | 长轨迹截短几乎完全破坏最终答案 |

因此 P0 给出的是“结构化正控制成立、因果依赖在熟悉分布上可见、组合泛化失败”的边界，不是“连续 latent 架构已经成立”。

## 3. P1：冻结 Qwen hidden → latent

### 3.1 接口合同

P1 保留 P0 的 `SharedStructuredTransition`，但初始 latent 不再由结构化 register 值直接初始化：

- Qwen3.5-2B 只进行一次文本编码；
- tokenizer 用 char `operation_spans` 生成逐步 token mask；
- hidden cache 保存 FP16 `last_hidden`、attention mask、operation token mask、operation mask、fingerprint 和版本；
- `max_length=512` 只作为硬性检查，遇到超长输入直接报错，不静默截断；
- 初始 state slots 与 query/control slot 通过 type embedding 分开读取 source hidden；
- 每个 latent step 只读取对应 operation span pooled hidden；
- warm-up heads 解码 start state、query register、operation family/source/target；teacher hidden/trace 不进入 student forward 或答案头。

- `src/yggdrasil_v2/reasoning_medium/a1_5_p1.py`

slot permutation 的 logit mean absolute delta 约 `1e-7`，说明 learned slots 没有被绑定到固定 register 名称；但 composition 与 same-answer shuffle 失败，不能把 ordinary split 的拟合写成无绑定 workspace 已泛化。

P2 synthetic smoke 仍保留为机制证据，但正式训练结果优先于 smoke。

## 5. 问题因果链

### 5.1 已排除：P0 不能执行 transition

32-example overfit、普通 validation/test full exact 和 transition-delta disable 结果表明：P0 的 mask、共享 transition、state CE、answer CE 和 checkpoint 链可以完成结构化状态更新。不能再把本轮失败简单归因于“recurrent architecture 完全不成立”。

### 5.2 仍存在：未见 composition 的操作组合无法组合

训练/普通 test 明确排除 `swap->copy`，composition split 只改变 family bigram，长度保持 2–4。P0 在 ordinary test 为 `1.0/1.0`，composition 为 `0.2734/0`；这说明 source/target/family 的单步编码和熟悉序列执行已学会，但 transition 对新 family 相邻关系没有足够的可组合性。当前 operation conditioning 仍是 learned embedding + cross-attention，尚没有可检查的 algebraic update 或专门的 relation binding。

P1 formal 复现同一边界：composition final `0.3242`、operation family `0.3546`、target `0.6675`、step state `0.3290`；因此问题不只属于 P0 的结构化输入，而是 frozen Qwen operation hidden 到递归 workspace 的组合绑定仍不稳。P2 learned-slot 的 composition final/state `0.2773/0` 与 same-answer shuffle failure 把这一问题继续保留下来。

### 5.3 长度答案与逐步 state 分离

length-heldout 的 final answer `1.0`，但 P0 state full exact `0.2266`；P2 formal 虽将 state full 提到 `0.6484`，仍未达到完整轨迹 Gate。这很可能是固定模板（首个 COPY、后续 SWAP 链）让答案头先学到结果映射；逐步 state probe 没有同步正确，因此不能把 length final 单项写成状态递归通过。

### 5.4 Qwen hidden 接口的主要风险曾是训练阶段不足，正式训练后已排除

small 300-step probe 的 validation state `0.4491`、final `0.2188` 只是 underfit；4096-cache 两阶段训练在 warm-up Gate 后把 validation final/state 提到 `1.0/1.0`。因此当前不能再把失败归因为 hidden→latent 接口完全不可行。仍需在 composition/length 与独立 matched text baseline 上检查泛化，而不是把 ordinary validation 拟合直接升级成架构通过。

### 5.5 visible text-CoT 基线的终止与成本边界

0.8B 单条 A1.5 smoke 可以在无人工长度上限下输出 88 tokens 并解析，但 128 条 test zero-shot formal 的 parse/final/state full 只有 `0.1797/0.0625/0.0234`；10 条样本触发 safety wall timeout，最长生成 `1088` tokens，峰值显存约 `1.74GB`。当前 runner 保留 `artificial_output_token_cap=null`，并支持显式、可审计的 per-example wall-time safety timeout；超时样本计为未终止/未解析，不被静默丢弃。这个结果暴露的是 visible baseline 终止/资源边界，不能用隐性 `max_new_tokens` 让成本看起来可控。

### 5.6 当前仍不能使用的成功口径

不能用 P0 train fit、P1 train warm-up、single final answer、loss、transition residual scale 或 P2 permutation smoke 宣称 A1.5 通过。P0 的因果干预也只能说明熟悉分布下确实使用 transition，不能证明 unseen composition 的轨迹忠实。

## 7. 下一步门禁

下一轮不能回到旧 K/T sweep。P1 ordinary hidden→latent 接口已建立，优先修正 P0/P2 的 operation-composition binding、same-answer identity dependence 与 length state fidelity，在同一 A1.5 schema 上重新满足：

1. P0/P1 的 ordinary、composition、length 都报告逐步 state exact 与 final answer；
2. composition final/state 必须显著高于 `prefix-2`；
3. full trajectory 必须明显优于 T=0、T=1、half trajectory；
4. no-op/delete/replace 必须改变对应中间 state 和最终答案，而不是仅改变预测置信度；
5. P1 保留 warm-up→joint、best reload 和 explicit span contract，并增加多 seed 与成本记录；
6. A1.5 未通过前不启动 A3/A4/V2-B。
