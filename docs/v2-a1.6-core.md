# Project-Yggdrasil V2-A1.6：最小核心——可寻址连续状态递归

## 研究问题与停止边界

A1.6 只验证一个问题：连续 latent state 是否能通过共享、可寻址的 relation transition 逐步执行 COPY/SWAP，并在结构化输入和文本 hidden 边界上保持同一能力。本轮不包含匿名 learned slots、K sweep、text-CoT、audit decoder、Boundary-MoE、FFN-MoE、动态停止、主动专家调用、多模态、RL、verifier reward、teacher trace 或多 seed。

本轮按 `data audit → 完整性测试 → C0 overfit32 → C0 formal → C0 因果 → C1-A → C1-B/final` 的顺序停止。C0-overfit32 的 Gate 只检查同一批 32 条训练样本的 fit；独立 validation 只作为 few-shot generalization diagnostic。

## 数据合同

数据 schema 为 `yggdrasil.v2-a1.6.relation-state-machine.v1`，seed 为 `20260715`。数据包含 `train/validation/test/length_heldout/relation_heldout/causal_core` 六个 split，记录初始值、query、每条 operation 的 family/source/target 字符 span、每步 state 和 operation mask。

`artifacts/v2-a/a1_6/data-audit.json` 的程序化 Gate 全部通过：

- causal_core necessary rate：`1.0`，共检查 2606 个删除单步反事实；
- relation holdout 的 `COPY amber -> jade` 在非 holdout split 为 `0`，在 relation split 覆盖率为 `1.0`；
- train 四种 family bigram 均为全部 bigram 的至少 10%；位置 1–4 COPY 均出现，COPY 比例均为 `0.5`；
- cross-split fingerprint overlap：`0`。

## C0 架构

`RelationAddressedCore` 只从三个 start value embedding 加 register key 初始化 slots。`RelationAddressedTransition` 是唯一 transition 实例，所有步骤共享。family、source-role、target-role 保持三路独立输入；source/target pointer 读取 register slots 后交给共享 operator MLP，再按 soft pointer 写回 slots。逐步 state decoding 与最终 answer 使用同一个 `shared_state_head`，没有 answer head、control slot、query content 写入、mean pooling 或绝对步 embedding。

完整性测试覆盖初始 state 与未来 operation 隔离、prefix 因果边界、query 不改变 trajectory、T=0、shared state head、无 `answer_head`、单 transition、pointer 归一化、三路 operation 输入和 C1 无整段 source cross-attention 等约束，当前为 `5 passed`。

## C0 overfit32 结果

按规定的 5000 steps、batch 32、learning rate `3e-4`、seed `20260715` 运行。训练子集五项 fit 指标全部为 `1.0`，因此 **C0-overfit32 Gate = PASSED**。此前停止是 overfit Gate 错误地包含独立 validation 所致，不是架构或训练失败。独立 validation 结果保留为 32-shot 泛化诊断：

| 指标 | fit 32 | few-shot validation diagnostic | Gate |
| --- | ---: | ---: | --- |
| final answer accuracy | 1.0 | 0.5625 | fit passed |
| state token accuracy | 1.0 | 0.6 | fit passed |
| state full exact | 1.0 | 0.1875 | fit passed |
| source pointer accuracy | 1.0 | 1.0 | fit passed |
| target pointer accuracy | 1.0 | 1.0 | fit passed |

该结果证明 sanity overfit 通过，但不证明泛化；few-shot validation diagnostic 不参与 overfit Gate，也不触发停止。formal C0 已从全新随机初始化开始，不加载 `c0-overfit32` checkpoint。

## 正式 C0 结果

正式 C0 使用完整 train split、6000-step 上限和规定配置启动，训练在 validation 连续满足 early-stop 条件后于 step 1100 停止，结果明确记录 `fresh_initialization=true`。ordinary test 与 length-heldout 的 trajectory/state full exact 均为 `1.0`，但 relation-heldout 为 `0.765625`，所以正式 C0 Gate **FAILED**，不运行 prefix/counterfactual 和 C1。旧协议还把一个最终 query token accuracy 与整条 trajectory 的全部寄存器 exact 直接比较；该比较不是有效的旁路检测，A1.7 已删除此 Gate，改为 answer logits 与 last-active queried state logits 的数值 identity。

## 后续只读诊断

A1.7 启动前对 `c0-formal/best.pt` 做了不训练、只读 checkpoint 的 closure diagnostic。relation-heldout 第一步全部正确，首次错误只从第 2 步开始；causal_core 也主要从第 2 步开始。四个 split 的 oracle-reset one-step overall accuracy 和 predicted hard re-embed diagnostic trajectory full 均为 `1.0`。因此 A1.6 的失败定位为连续 latent 写回缺少递归闭包，而不是 pointer 或单步 COPY/SWAP operator 失败。

旧 relation-heldout 还同时改变了多个 family×directed-pair 组合和 relation sequence 分布，不能被解释为严格的单变量 holdout。诊断 artifact 位于 `artifacts/v2-a/a1_6/diagnostics/closure-diagnostic.json`；hard re-embed 没有进入后续正式架构。

## 当前结论

当前能够声称：数据合同和程序化 audit Gate 成立；A1.6 的 RelationAddressedCore 结构完整性成立；C0-overfit32 fit-only sanity 通过；正式 C0 在 ordinary test 和 length-heldout 上 state full exact 为 `1.0`，pointer supervision 为 `1.0`。

当前不能声称：C0 在原 relation holdout 或 causal intervention 上成立；无 closure 约束的 A1.6 连续状态递归完成完整因果执行；C1 文本 hidden 边界可用；A1.6 架构 Gate 通过。
