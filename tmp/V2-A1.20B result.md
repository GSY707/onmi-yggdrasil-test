## 失败结果

best checkpoint 在 step 4000。2048 条 heldout validation：

- trajectory full exact `0.297363`；
- final state full exact `0.409668`；
- state token `0.547742`；
- answer `0.608887`；
- 最差 N×T cell mapping/trajectory/answer `0.315341/0/0.227273`。

完整 Boundary 输出逐样本同时正确仅 `0.087891`。N4 的全部 value 正确率为 `0.007331`，完整 Boundary 正确率 `0.001466`；T13–16 的完整 program、source 序列与 target 序列 exact 均为 `0`。

## 根因

全 oracle Boundary 驱动同一 frozen core 时 trajectory/final/answer 全部为 `1.0`，所以 A1.19H core 不是本轮失败源。

主要错误是匿名实体的 value 与 source/target binding；family sequence 是次要但实质错误。只把 value+source+target+query 替换为 oracle，trajectory 可从 `0.297363` 恢复到 `0.802734`。

当前训练还有结构性信用断裂：mask 的阈值和 family/pointer 的 `argmax` 位于 frozen core 之前。实测 state CE 只给 value logits 与 continuous payload 梯度，对 entity/operation presence、family、source、target、query logits 的梯度全部为 `0`。这些控制只靠独立局部 CE 学习，局部错误在长程序中组合放大。
