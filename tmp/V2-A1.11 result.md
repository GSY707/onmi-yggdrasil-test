# V2-A1.11 结果：A1.10 不是纯组合故障，匿名通用 reasoner 是充分的独立失败源

日期：2026-07-16

## 结论

A1.11 的 2×2 正交诊断已经完成。主结论不是“boundary 和 reasoner 单独都好，只有组合时坏”，而是：

1. exact symbolic typed roles 直接输入匿名 `K=8` 通用 recurrent reasoner 时，overfit32 可以严格拟合，但三组正式实验为稳定 `0/3`；因此无需 full-text boundary，reasoner 臂自身就足以复现失败。A1.10 的失败不是纯组合效应。
2. full-token learned boundary → frozen A1.8 core 在 overfit32 上的 trajectory、answer 和 role mapping 都为 `1.0`，但 frozen core 的 source/target pointer 最低均为 `0.9642857143`，严格内部接口 Gate 失败。只读 hard re-embedding 后所有指标恢复 `1.0`，说明还存在一个连续 latent → frozen prototype/address geometry 的次级接口缺陷。
3. 当前证据能定位到“匿名 workspace + generic recurrent transition + 当前目标函数”这一整臂，但还不能把匿名 slot binding 与 generic transition 分开。也不能据此证明任何通用 Transformer 在数学上都做不到；被否定的是当前 `K=8, D=256, 2 shared blocks, mean readout, state CE + answer CE` 合同。

因此最强归因是：**主要故障在 reasoner 的状态绑定／逐步转移归纳偏置不足，boundary 连续接口另有独立风险；不是两个健康组件组合后才产生的问题。**

## 实验矩阵

| 输入边界 | structured A1.8 core | anonymous generic reasoner |
| --- | --- | --- |
| oracle/exact symbolic typed roles | A1.9：`3/3` passed | A1.11-Reasoner：overfit32 passed，formal `0/3` |
| learned full text | A1.11-Boundary：严格 overfit32 failed，formal stopped | A1.10：formal `0/3` |

Boundary 和 Reasoner 两臂独立初始化、独立判定。任何 ordinary formal 失败的 run 都未运行 intervention；未运行不记作 intervention failed。

## Boundary 臂

该臂使用 A1.10 已审计的完整 frozen-Qwen last hidden 与 attention mask，不使用 oracle span；learned typed reader 输出 start/query/family/source/target latent，驱动完全冻结的 A1.8 core。operation count/mask 保留，因为本臂只隔离 span discovery。

首次实现曾在 reader 输出后加入 LayerNorm，它会改变 frozen core prototype 的可达几何；该实现已废弃且产物删除。修正后的 fresh run 不含该 LayerNorm，训练 5000 steps，best step 1600：

| 指标 | overfit32 最差长度 |
| --- | ---: |
| trajectory full exact | `1.0` |
| final answer | `1.0` |
| typed mapping minimum | `1.0` |
| source pointer | `0.9642857143` |
| target pointer | `0.9642857143` |
| frozen core hash | unchanged |

按预注册 pointer 必须为 `1.0`，所以 overfit Gate 失败并停止 formal。随后只做了不改变 checkpoint 的 hard re-embedding 诊断：把 reader mapping argmax 重新嵌入 frozen core prototypes 后，T1–16 trajectory、answer、source/target pointer 全部为 `1.0`。

这表明 full text 上的离散角色识别已经成功，缺陷位于连续输出与 frozen core 地址几何的精确接口。由于正式训练没有运行，不能进一步声称 learned full-text boundary 的 task-level heldout generalization 已失败。

## Reasoner 臂

为保证正交性，本臂最终没有使用 Qwen、A1.9 role cache 或 adapters。输入直接由不可变 A1.8 records 构造为精确 value/family/register one-hot、role-type one-hot 和固定 sinusoidal operation-step features；structured core 完全不加载。此前短暂实现的 continuous-adapter 版本混入了 boundary 几何，产物已删除，不属于正式证据。

exact-symbolic overfit32 在 best step 800 达到 T1–16 trajectory/final/answer 全 `1.0`，step 1000 连续两次满足严格 Gate 后停止。这证明 2,924,072 个可训练参数具有记忆 32 条样本的容量。

三组 fresh formal 结果如下：

| run | steps / best | short traj | in-range traj | relation traj | T20/24 traj | relation OOD traj | causal traj |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | `3400 / 2200` | `0.002604` | `0.001302` | `0` | `0.001302` | `0` | `0.001953` |
| 2 | `2800 / 1600` | `0.002604` | `0` | `0.002604` | `0.001302` | `0` | `0.001953` |
| 3 | `2600 / 1400` | `0.001302` | `0` | `0` | `0.003906` | `0` | `0` |

final state 也没有接近 Gate：short 为 `0.0664–0.0703`，in-range 为 `0.1667–0.1797`，relation in-range 为 `0.1497–0.1810`。answer 约为 `0.30–0.38`，与几乎为零的 trajectory 明显脱钩。所有正式 split 的最低 state-token 只有 `0.3163–0.3387`。

更关键的是，best checkpoint 在训练集均衡子集上的 fit diagnostic 也只有：trajectory `0–0.003906`、final state `0.1523–0.1641`、answer `0.3711–0.3809`。所以失败不只是 length/relation heldout 的组合泛化问题；当前训练在大分布上连训练子集的逐步算法都没有形成，只在 overfit32 小样本上完成了记忆。

## 可能机制

最符合证据的机制有三个，它们不是三个已被分别证明的唯一原因，而是下一步需继续拆分的候选：

1. **状态实体没有稳定地址。** 八个 slot 只由 learned queries 初始化，输出又对 slot 做 permutation-invariant mean readout；模型没有被迫建立“哪个 latent 对应哪个 register”的持久绑定。它可以记住少量程序，但难以把 source/target identity 变成可复用的状态更新规则。
2. **递归步与程序步没有硬对齐。** 每个 recurrent step 都重新 cross-attend 全部 operation sequence，没有 cursor、selected-operation contract 或显式 halting/persistence mechanism。state CE 可以奖励统计性的终点近似，却不强迫第 `t` 次 recurrence 执行第 `t` 个 operation。
3. **目标函数没有约束 transition identity。** state/answer CE 只约束 readout；latent state 本身不需要保持可寻址、可复用的实体结构。answer 达到约 `0.3–0.38` 而 trajectory 近零，正是终点/分布捷径比逐步执行更容易优化的表现。

Boundary 的次级问题则更具体：mapping 分类为 `1.0` 不代表连续 latent 落在 frozen core 的 prototype/address basin 内。hard re-embedding 完全修复说明这里需要一个受约束的离散或 prototype-anchored 接口，而不是继续让任意连续向量自己对齐冻结几何。

## 下一步

不要继续对 A1.10 调 K、层数、recurrent steps 或 loss 权重。下一阶段应只拆 Reasoner 臂内部：先恢复最小 entity-addressable state workspace，同时保留通用 learned recurrent block 与 exact symbolic roles；如果它通过，则匿名 binding 是主因；如果仍失败，则问题更集中在 operation-step alignment／generic transition objective。之后再决定是否值得测试匿名 workspace 与结构化 transition 的对称格子。

Boundary 暂不扩大 formal。若未来重新进入该臂，应把输出合同直接切换为 prototype-anchored/discrete addressing，并重新预注册 Gate；hard re-embedding 只作为诊断，不能偷偷成为旧架构的救援补丁。
